Panoramica

astro cerca un indicatore su tutte le fonti di threat intelligence configurate e ne riassume il risultato. Il flusso tipico è: Ricerca o Estrazione degli indicatori → raccolta in un Caso → note e analisi → Export del report.

Tutto gira sul server dove è installato astro: la ricerca contatta solo le fonti online abilitate, i dataset offline (MITRE ATT&CK, CISA KEV, registro MAC IEEE) restano in locale.

Ricerca

Nella pagina Ricerca scrivi uno o più indicatori. Il tipo viene riconosciuto in automatico: hash MD5/SHA1/SHA256/SHA512, IPv4/IPv6, domini, URL, email, CVE, ID ATT&CK (es. T1059.001, G0032), indirizzi MAC e nomi liberi (es. Lazarus Group). Gli indicatori "defanged" come hxxps://evil[.]com sono accettati.

  • Un indicatore per riga: ogni riga deve essere un indicatore valido.
  • Estrai dal testo: incolla un log, un'email o un report; astro trova da solo tutti gli indicatori.
  • Carica un file: come "Estrai dal testo", per log e report su file (fino a 8 MB).
  • Salva nel caso: i risultati vengono salvati direttamente in un caso aperto.
  • Fonti e opzioni: Solo offline usa solo i dataset locali, Ignora risultati in cache forza una nuova interrogazione, Solo queste fonti limita la ricerca.

Ogni risultato mostra il verdetto di ogni fonte, i dettagli (proprietario dell'IP, famiglia di malware, CVSS…) e il link alla pagina della fonte. "Copia defanged" copia l'indicatore in forma sicura da incollare in chat e report.

Verdetti

malevoloLa fonte lo considera dannoso (es. ≥ 5 motori su VirusTotal, campione su MalwareBazaar, C2 su ThreatFox ad alta confidenza).
sospettoSegnalazioni deboli o storiche (poche detection, pulse OTX, URL non più online).
pulitoLa fonte lo conosce e non lo ritiene dannoso.
infoInformazioni senza giudizio: ATT&CK, CVE, vendor MAC, porte aperte.

Il verdetto complessivo di un indicatore è il più grave tra quelli delle fonti. Le domande frequenti alle fonti sono tenute in cache (1–24 ore secondo la fonte) per rispettare le quote dei piani gratuiti.

Estrazione

Estrazione trova, normalizza e de-duplica gli indicatori in un testo o file senza interrogare nessuna fonte. Dalla tabella puoi selezionarli e cercarli, oppure aggiungerli a un caso (anche cercandoli subito).

Casi

Un caso raccoglie gli indicatori di un'indagine con l'ultimo risultato di ognuno, note, tag e una marcatura TLP. Puoi riprenderlo in qualsiasi momento.

  • Aggiungi indicatori: da elenco, testo o file, con nota opzionale e ricerca immediata.
  • Cerca nuovi interroga solo gli indicatori mai cercati; Cerca di nuovo tutti aggiorna ogni risultato.
  • Note: timeline e conclusioni in Markdown, riportate negli export.
  • Chiudi un caso concluso (resta consultabile in "Includi chiusi"); Elimina lo cancella definitivamente, dopo aver scritto il suo nome.

TLP (Traffic Light Protocol 2.0)

TLP:REDSolo per i presenti/destinatari, non si condivide oltre.
TLP:AMBER+STRICTSolo all'interno della propria organizzazione.
TLP:AMBEROrganizzazione e suoi clienti, secondo necessità (predefinito).
TLP:GREENComunità di riferimento, non pubblicamente.
TLP:CLEARNessuna restrizione.

Fonti e dataset

Fonti elenca le fonti e il loro stato. Le fonti online ricevono l'indicatore cercato; quelle offline leggono i dataset locali. Sincronizza i dataset (MITRE ATT&CK, CISA KEV, registro MAC) al primo avvio e poi periodicamente: la dashboard avvisa se hanno più di 30 giorni.

Alcune fonti non richiedono chiavi: rdap (data di registrazione, registrar, proprietario della rete e contatto abuse; un dominio registrato da meno di 30 giorni è sospetto), dns (record A, AAAA, CNAME, MX, NS, TXT e DNS inverso), hostinfo (analisi offline: dominio registrabile, suffissi di hosting, caratteri ingannevoli come аpple.com con una "а" cirillica, nomi generati da algoritmi) e wikipedia (riassunto per gruppi, malware e CVE famose).

Chiavi API

In Chiavi API inserisci le chiavi delle piattaforme (VirusTotal, abuse.ch, AbuseIPDB, OTX, Shodan, GreyNoise, NVD). Le fonti si attivano subito, senza riavviare. "Test" esegue una ricerca innocua (file di test EICAR, 8.8.8.8, CVE-2021-44228…) per verificare la chiave. Le chiavi non vengono più mostrate dopo il salvataggio. Se una chiave è impostata da variabile d'ambiente ha la precedenza e qui risulta bloccata.

Token di accesso e REST API

I token di accesso servono per entrare in questa interfaccia e per la REST API (Authorization: Bearer …). Un token si vede solo alla creazione; revocandolo si chiudono anche le sue sessioni. Crea un token per ogni integrazione (es. sentinelone) così da poterlo revocare separatamente.

La REST API è documentata in /api/v1/openapi.json. Per SOAR ed EDR (es. SentinelOne Hyperautomation) usa POST /api/v1/enrich: invii il testo di un alert e ricevi un verdetto complessivo con gli indicatori malevoli e sospetti.

Sicurezza e OPSEC

  • Le fonti online (VirusTotal in particolare) possono condividere le ricerche: per indicatori sensibili o interni usa Solo offline.
  • Le ricerche DNS passano da DNS-over-HTTPS (Cloudflare) e non compaiono nei log del DNS locale o aziendale, ma i name server del dominio vedono comunque una richiesta; RDAP interroga il registro del dominio. Se il dominio è controllato dall'attaccante, usa Solo offline o escludi queste fonti.
  • Il server ascolta solo su localhost salvo configurazione esplicita; per esporlo usa TLS.
  • I dati delle fonti sono trattati come non fidati e mostrati in modo sicuro.

Overview

astro searches an indicator across every configured threat intelligence source and summarizes the outcome. A typical workflow is: Search or Extract indicators → collect them in a Case → add notes and analysis → Export the report.

Everything runs on the server where astro is installed: searches only contact the enabled online sources, while the offline datasets (MITRE ATT&CK, CISA KEV, IEEE MAC registry) stay local.

Search

On the Search page, enter one or more indicators. Their type is detected automatically: MD5/SHA1/SHA256/SHA512 hashes, IPv4/IPv6, domains, URLs, emails, CVEs, ATT&CK IDs (e.g. T1059.001, G0032), MAC addresses and free-text names (e.g. Lazarus Group). Defanged input such as hxxps://evil[.]com is accepted.

  • One per line: each line must be a valid indicator.
  • Extract from text: paste a log, an email or a report and astro finds every indicator in it.
  • Upload a file: like "Extract from text", for logs and reports on file (up to 8 MB).
  • Save to case: the results go straight into an open case.
  • Sources and options: Offline only uses only local datasets, Ignore cached results forces fresh queries, Only these sources narrows the search.

Each result shows the verdict of every source, its details (IP owner, malware family, CVSS…) and a link to the source page. "Copy defanged" copies the indicator in a form that is safe to paste in chats and reports.

Verdicts

maliciousThe source considers it harmful (e.g. ≥ 5 VirusTotal engines, a MalwareBazaar sample, a high-confidence ThreatFox C2).
suspiciousWeak or historical reports (few detections, OTX pulses, URLs no longer online).
cleanThe source knows it and does not consider it harmful.
infoInformation without a judgement: ATT&CK, CVEs, MAC vendors, open ports.

The overall verdict of an indicator is the most severe among its sources. Source answers are cached (1–24 hours depending on the source) to respect free-tier quotas.

Extract

Extract finds, normalizes and de-duplicates the indicators in a text or file without querying any source. From the table you can select them and search them, or add them to a case (optionally searching them right away).

Cases

A case collects the indicators of an investigation with the latest result of each, notes, tags and a TLP marking. You can resume it at any time.

  • Add indicators: from a list, text or file, with an optional note and an immediate search.
  • Search new queries only the indicators never searched; Search all again refreshes every result.
  • Notes: timeline and findings in Markdown, carried into the exports.
  • Close a finished case (it stays available under "Include closed"); Delete removes it permanently after you type its name.

TLP (Traffic Light Protocol 2.0)

TLP:REDFor the eyes and ears of individual recipients only, no further disclosure.
TLP:AMBER+STRICTOnly within the recipient's organization.
TLP:AMBERThe organization and its clients, on a need-to-know basis (default).
TLP:GREENWithin the community, not publicly.
TLP:CLEARNo restrictions.

Export

From a case's Export menu:

FormatWhat it is for
PDF reportA document to hand over or print: summary, indicator table (defanged), results by source and notes. The TLP label is printed at the top and bottom of every page, as TLP 2.0 requires.
MarkdownA readable report to paste into tickets, wikis or write-ups (e.g. Hack The Box). Indicators are defanged and source data is neutralized.
JSONAll the case data, including full results: for scripts and automation.
STIX 2.1A bundle for threat intelligence platforms (MISP, OpenCTI…). It holds indicators with patterns, vulnerabilities, ATT&CK techniques and groups, marked with the official OASIS TLP. IDs are stable: exporting the same case again does not create duplicates.
ATT&CK NavigatorA layer to open in MITRE ATT&CK Navigator ("Open Existing Layer" → "Upload from local"): case techniques in red, techniques referenced by threat intel on its indicators in orange.

Exported files contain TLP-marked data: share them according to the case marking.

Sources and datasets

Sources lists the sources and their status. Online sources receive the searched indicator; offline ones read local datasets. Sync the datasets (MITRE ATT&CK, CISA KEV, MAC registry) on first use and then regularly: the dashboard warns when they are older than 30 days.

Some sources need no key: rdap (registration date, registrar, network owner and abuse contact; a domain registered less than 30 days ago is suspicious), dns (A, AAAA, CNAME, MX, NS, TXT records and reverse DNS), hostinfo (offline analysis: registrable domain, hosting suffixes, look-alike characters such as аpple.com with a Cyrillic "а", algorithmically generated names) and wikipedia (summary for groups, malware and famous CVEs).

API keys

In API keys you enter the keys of the platforms (VirusTotal, abuse.ch, AbuseIPDB, OTX, Shodan, GreyNoise, NVD). Sources are enabled immediately, without a restart. "Test" runs a harmless lookup (the EICAR test file, 8.8.8.8, CVE-2021-44228…) to check the key. Keys are never shown again once saved. A key set by an environment variable takes precedence and is locked here.

Access tokens and REST API

Access tokens sign in to this interface and authenticate the REST API (Authorization: Bearer …). A token is shown only when created; revoking it also ends its sessions. Create one token per integration (e.g. sentinelone) so you can revoke them separately.

The REST API is described in /api/v1/openapi.json. For SOAR and EDR tools (e.g. SentinelOne Hyperautomation) use POST /api/v1/enrich: send the text of an alert and get an overall verdict with the malicious and suspicious indicators.

Security and OPSEC

  • Online sources (VirusTotal in particular) may share searches: use Offline only for sensitive or internal indicators.
  • DNS lookups use DNS-over-HTTPS (Cloudflare) and stay out of local or corporate resolver logs, but the domain's name servers still see a query; RDAP asks the domain's registry. If the attacker controls the domain, use Offline only or leave these sources out.
  • The server listens on localhost unless configured otherwise; use TLS to expose it.
  • Source data is treated as untrusted and always displayed safely.
